# 摸鱼看盘轻量多形态与实时性总开发计划

> 状态：M1 已实现且 L1 人工 GUI 验收通过，待交易时段 60 分钟实时性终验；M2 Excel 轻量工作台已完成并冻结范围；M3 本地工作网页已完成并冻结范围，采用高密度通用工作门户与按需趋势图
> 日期：2026-07-12
> 适用平台：Windows 优先
> 当前基线：现有 Electron 悬浮窗、托盘、行情双源、市场概览、新闻、AI、提醒和本地持久化保持可用
> 前置文档：`docs/2026-07-10-personal-stock-widget-round-2-optimization-plan.md`

## 1. 总体结论

后续不重做行情内核，也不发展成 Office 加载项、浏览器插件、电子表格软件或通用建站工具。产品演进为一个本地 Electron 应用提供多种轻量展示形态：

```text
现有行情、新闻、AI、提醒和本地数据核心
                    │
              统一展示快照
       ┌────────────┼────────────┐
       │            │            │
   L0/L1/L2      Excel 外观壳   本地工作网页
   Electron        Electron       普通浏览器
```

阶段顺序确定为：

1. 第一阶段：实时性改造 + L0 托盘状态 + L1 速览弹窗，保留现有窗口为 L2。
2. 第二阶段：增加高相似度 Excel 外观的 Electron 工作台，但不实现 Excel 内核。
3. 第三阶段：增加本地低调工作网页，使用固定模板和有限自定义，不实现网页生成器。

每个阶段单独验收。上一阶段未稳定，不进入下一阶段。

## 2. 产品目标与硬边界

### 2.1 目标

- 平时尽可能没有持续占屏的行情窗口。
- 用户可以从托盘快速判断市场、自选和重要事件状态。
- 用户主动查看时，感知刷新速度从当前约 8 秒提高到约 3 秒。
- 用户不主动查看时，降低请求、渲染和资源占用。
- Excel 和网页形态只改变外观与信息组织，不复制业务逻辑。
- 所有形态继续共享同一份行情质量、新闻、AI、提醒和隐私边界。

### 2.2 明确不做

- 不做 Office Excel/Word 加载项。
- 不做浏览器扩展。
- 不接入真实 Excel 进程，不读写 XLSX，不实现公式、宏、数据透视表或完整单元格编辑。
- 不实现通用电子表格内核。
- 不实现拖拽式低代码平台、通用 CMS 或任意网页生成器。
- 不允许本地网页执行用户提供的任意 HTML、CSS 或 JavaScript。
- 不使用 Microsoft/Excel 商标、图标、产品名称、签名或原始视觉资源。
- 不把应用伪装成系统组件，不追求对任务管理器、安装清单或专业检查的隐藏。
- 不改变现有“个人低频查看、非专业行情终端、非投资建议”的产品定位。

### 2.3 轻量原则

- 优先复用 Electron、原生 TypeScript、CSS 和 Node 内置模块。
- 不为了换皮引入大型 UI 框架、电子表格库或 Web 服务框架。
- 新展示形态只消费脱敏展示快照，不直接调用 provider、SQLite 或 AI。
- 默认只创建当前需要显示的窗口；隐藏窗口不持续做完整 DOM 重绘。
- 每个阶段先做一个完整而窄的形态，再决定是否增加模板或细节。

## 3. 目标展示层级

### 3.1 L0：托盘状态

平时只保留系统托盘图标，不显示主窗口。

展示能力：

- 图标状态：平稳、整体上涨、整体下跌、重要提醒、数据异常。
- Tooltip：主要指数、自选涨跌数量、重要事件数量、数据更新时间。
- 右键菜单：三至五个重点自选、最近提醒、显示速览、显示完整窗口、设置和退出。
- 不尝试在 Windows 托盘图标内绘制完整价格数字。

### 3.2 L1：托盘速览弹窗

独立的无边框 `quickWindow`，建议约 `320 × 380`：

- 从当前托盘图标附近弹出。
- 不占任务栏，失去焦点自动隐藏。
- 显示三个指数、最多五个重点标的和一条重要事件。
- 只保留“完整查看”“暂停/恢复提醒”等必要操作。
- 首屏先显示最近可信缓存，同时立即发起刷新。
- 不包含完整新闻、设置、日 K、BOLL 和复杂风险配置。

### 3.3 L2：现有完整窗口

现有悬浮窗继续承担：

- 持仓、自选、市场和 AI 驱动页面。
- 图表详情。
- 完整风险信息和新闻。
- 设置入口与现有窗口能力。

L2 不因 L0/L1 引入而重写。

### 3.4 Excel 外观工作台

一个新的 Electron 窗口外壳，视觉上接近常见 Excel 工作表，但只实现足以维持真实观感的浅交互：

- 标题栏和窗口按钮。
- Ribbon 标签和少量真实可用按钮。
- 名称框、`fx` 区域和公式栏外观。
- 行号、列标、网格、滚动条和工作表标签。
- 单元格选择、方向键移动、滚动和 Sheet 切换。
- 行情更新只更新对应单元格，不重建整个网格。

不实现公式计算、自由编辑、文件保存、XLSX 兼容和完整 Ribbon。

### 3.5 本地低调工作网页

由 Electron 在 `127.0.0.1` 随机端口提供的普通网页，可在用户浏览器中打开。

首版只支持固定模块：

- 今日待办。
- 项目进度。
- 工作日志。
- 常用链接。
- 自定义文字和简单表格。
- 行情摘要。
- 重要动态。

允许配置标题、模板、模块显示、顺序、文字、别名和少量主题颜色；不允许任意代码和任意布局引擎。

## 4. 实时性目标与依据

### 4.1 当前问题

当前默认行情间隔为 8 秒，实际调度是“请求完成后再等待约 7.2–8.8 秒”，所以真实起点间隔还会叠加网络耗时。配置层当前最低限制为 5 秒。

现有双源真实测量基线（2026-07-12，周日，仅代表网络和解析耗时）：

| 数据源 | 10 只股票批量请求中位耗时 | 本轮最慢 | 返回数量 |
| --- | ---: | ---: | ---: |
| 东方财富 | 47ms | 259ms | 10/10 |
| 腾讯 | 65ms | 158ms | 10/10 |

Level-1 个股快照通常是约 3 秒粒度，部分指数约 5 秒（参考：[上交所 Level-1 行情快照说明](https://www.sseinfo.com/services/assortment/market/hqywwd/wdkfcsjk/c/10812328/files/7e7f11681df748a9a767f6c619cecbb4.pdf)）。东财和腾讯属于无 SLA 的网页型二次分发源，因此不能承诺严格等于交易所发布节奏。

### 4.2 最终刷新策略

| 状态 | 自选股 | 指数 | 重型市场概览 | 新闻 |
| --- | ---: | ---: | ---: | ---: |
| L1/L2/Excel 窗口可见 | 3 秒 | 5 秒 | 15 秒以上 | 60 秒 |
| 本地网页可见 | 3 秒 | 5 秒 | 15 秒以上 | 60 秒 |
| 只有 L0 托盘后台 | 5 秒 | 5 秒 | 15 秒以上 | 60 秒 |
| 网页进入后台标签页 | 5 秒 | 5 秒 | 15 秒以上 | 60 秒 |
| 午休、盘前、收盘后、周末、休市 | 60 秒 | 60 秒 | 60 秒以上 | 原策略 |

补充规则：

- 打开任一展示窗口时立即刷新一次，不等待定时器。
- 网络恢复、电脑唤醒、自选变化后立即刷新一次。
- 不提供 1 秒或 2 秒模式。
- 设置页只提供“标准”和“较快”档，不允许任意填写极小间隔。

### 4.3 调度改造要求

- 从“完成后再等待完整间隔”改为“请求起点到下一请求起点”的目标周期。
- 保持 single-flight，禁止请求重叠、补发和追赶风暴。
- 保留约 ±5% 抖动。
- 行情专用超时调整为 2–2.5 秒；新闻和 AI 保持独立超时。
- 主源失败后才请求备用源，正常轮询不长期并发双源。
- 双源交叉校验从“每 6 轮”改为“每 30–60 秒”。
- 恢复探测、熔断和健康窗口从循环次数改为真实时间。
- 数据未变化时不反复推送完整 DOM；保留低频健康心跳。

### 4.4 快速与重型市场数据拆分

不能把当前完整市场概览直接缩短到 3 秒。应拆成：

```text
快速层
├── 自选股：3/5 秒
└── 三个指数：5 秒

慢速层
├── 市场宽度：15 秒或更慢
├── 行业排行：继续使用分钟级缓存
├── 分时预览：15–30 秒
└── 日 K：按需加载
```

快速指数刷新不得触发行业、分时和完整市场缓存的重复写入。

## 6. 第二阶段：轻量 Excel 外观 Electron

### 6.1 阶段目标

增加一个乍看接近常见 Excel 工作表的普通 Electron 窗口，用来展示同一份行情快照。目标是高相似度外观与基本可信交互，不是电子表格能力。

### 6.2 实现策略

- 使用独立 `excelRenderer.ts` 和 `excel.css`。
- 不在现有 `styles.css` 上叠加大量 Excel 特例。
- 使用稳定 DOM 网格，行情刷新只替换单元格文本和状态类。
- 复用共享格式化函数和展示 ViewModel，不复制 provider、风险、新闻和 AI 逻辑。
- 使用原生 CSS Grid 或普通 DOM；首版不引入电子表格组件库。
- 作为普通可调整、可最大化的任务栏窗口，不使用透明和始终置顶。

### 6.3 最小视觉结构

- [x] 自定义标题栏和窗口控制。
- [x] `文件 / 开始 / 插入 / 页面布局 / 公式 / 数据 / 审阅 / 视图` 标签。
- [x] 只有少量真实动作的 Ribbon；其余区域作为静态视觉结构，不堆满死按钮。
- [x] 名称框、`fx`、公式栏。
- [x] A–Z 列标、行号、网格线和滚动区域。
- [x] 工作表标签、状态栏和缩放外观。
- [x] 单元格选择框、方向键、滚动和 Sheet 切换。

### 6.4 数据工作表

首版固定三张 Sheet，名称可配置：

1. `工作台`：指数、自选摘要和状态。
2. `项目明细`：自选股二维表。
3. `动态记录`：重要事件和更新时间线。

实现结果：当前分别落为“项目总览”“进度跟踪”“动态记录”，均从统一 `AppSnapshot` 映射生成；不展示持仓成本、数量和账户规模。

允许配置：

- Sheet 名称。
- 股票别名。
- 列标题。
- 红绿色是否启用。
- 展示哪些标的和字段。

不允许配置任意公式、任意单元格脚本和任意文件模板。

### 6.5 第二阶段验收与审查点

- 行情刷新不丢失选区、Sheet、滚动位置和 Ribbon 状态。
- 100%、125%、150% 缩放和常见窗口尺寸下无错位。
- 视觉结构完整，不依赖 Microsoft 原始图片或图标。
- 常用交互可用；未实现的功能不伪装成可点击核心功能。
- Excel 窗口隐藏后不继续高频完整渲染。
- 关闭 Excel 外观模式不影响 L0/L1/L2。

停止审查：

- 先交付一张 `工作台` 的高相似度静态原型并进行截图验收。
- 外观方向确认后才接入实时数据和另外两张 Sheet。
- 不因“更像”增加公式、文件格式、自由编辑或电子表格内核。

实施记录（2026-07-12）：静态原型已由用户确认外观方向；随后完成统一 Excel 展示 ViewModel、自选/指数/资讯三张动态工作表和单元格增量刷新。Excel 窗口可见时纳入前台刷新策略，打开时主动刷新，但不创建新的 provider 或轮询器。另增加受限的“工作记录”Sheet（8 列 × 20 行、编辑栏输入、本地自动保存）和按需加载的“趋势分析”Sheet（原生 SVG、最近 60 个交易日、收盘线及 BOLL 上中下轨）。趋势页复用已有日线接口与本地 BOLL 结果，不进入 3 秒轮询。真实 Electron 窗口已验证五张工作表、行情与资讯数据、刷新后选区保持、工作记录编辑入口及 BOLL 图表；供应商名和持仓隐私不进入工作表。自动测试 155 项通过，完整构建通过。M2 功能范围至此冻结，不再扩展为公式、自由建表或通用图表引擎；常见 Windows 缩放组合留待后续回归矩阵。

预计工作量：8–15 个开发日。

## 7. 第三阶段：本地低调工作网页

### 7.1 阶段目标

在普通浏览器标签页中提供一个真正可用于简单工作记录的本地页面，行情只是其中一个低调模块。页面可有限定制，但不发展成网站生成器。

### 7.2 最小本地服务

建议使用 Node 内置 `http`，不引入 Express：

```text
127.0.0.1:<随机端口>/
├── GET /                    本地页面
├── GET /api/public-snapshot 脱敏只读快照
└── GET /api/events          SSE 更新
```

安全要求：

- [x] 只绑定 `127.0.0.1`，不监听局域网地址。
- [x] 每次启动生成随机访问令牌。
- [x] 校验 Host、Origin 和访问令牌，防止任意网页读取本地服务。
- [x] 行情和资讯仅提供读取接口；网页可发送临时可见性状态，但不能写 Electron 设置。
- [x] 新建 `PublicSnapshot`，明确排除 API Key、持仓数量、成本、账户规模、原始新闻 URL 和内部文件路径。
- [x] Electron 退出时关闭端口和 SSE 连接。
- [x] 页面使用严格 CSP，不加载远程脚本和字体。

### 7.3 首版模板与自定义

首版先完成一个“项目进度工作台”模板：

- 今日待办。
- 项目进度表。
- 工作日志。
- 常用链接。
- 行情摘要。
- 重要动态。

首版确认后，再考虑增加：

- 周工作记录模板。
- 知识笔记/资料导航模板。

允许自定义：

- 页面标题和副标题。
- 模块显示、顺序和少量宽度预设。
- 待办、日志、链接、普通文字和简单表格内容。
- 股票别名、行情模块位置和默认显隐。
- 预设主题和少量颜色。

禁止自定义：

- 任意 HTML、CSS、JavaScript。
- 任意远程 iframe。
- 任意本地文件读取。
- 拖拽画布、插件系统和脚本组件。

### 7.4 页面可见性与刷新

- 页面打开时先显示最近可信缓存。
- 使用 SSE 接收行情变化，不在每个浏览器标签页重复轮询上游 provider。
- 浏览器 `visibilitychange` 通知 Electron 当前是否需要前台 3 秒模式。
- 所有网页客户端只共享 Electron 的一套行情轮询。
- 页面隐藏后降低前端渲染频率和心跳，不关闭后台提醒。

### 7.5 第三阶段验收与审查点

- 普通浏览器可打开并长期保持连接。
- 关闭浏览器不影响 Electron 托盘和提醒。
- 网页无法读取敏感配置和完整内部快照。
- 多开两个标签页不会让上游行情请求翻倍。
- 页面内容可保存、恢复和导出为应用配置的一部分。
- 页面断开后能重连 SSE，并明确显示缓存/断开状态。
- Electron 退出后本地端口立即关闭。

停止审查：

- 先验收一个可真实使用的项目工作台模板。
- 模板没有实际使用价值时，不继续增加模板和配置项。
- 第二、第三模板必须复用同一固定模块系统，不引入自由画布。

## 13. 完成定义

只有同时满足以下条件，整项计划才算完成：

- L0/L1 成为默认低干扰入口，L2 原功能没有回归。
- 前台 3 秒、后台 5 秒经过真实交易时段验证，且没有限流、堆积或重复提醒。
- 指数快速刷新不带动行业、分时和缓存高频工作。
- Excel 形态在常见缩放下具有可信外观，但没有演变成电子表格内核。
- 本地网页真正可用于有限工作记录，但没有演变成建站系统。
- 三种新形态均不复制 provider、AI、SQLite 和提醒逻辑。
- 本地网页不暴露持仓隐私、凭据和内部路径。
- 多窗口、多网页标签页不会增加上游轮询器数量。
- 全量测试、构建、真实 smoke、Windows 打包和完整交易日运行均通过。
